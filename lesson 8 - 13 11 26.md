#### Text as numbers, ASCII and Unicode :

#### The big Question :

So far we’ve stored numbers in bulbs. but your name is not a number. How does a computer store the letter “S” ?

computer can’t store a letter. It can only store 0s and 2s. So people made a deal: Give every letter a number, and store the number.

Think of a school with roll numbers. the teacher doesn’t write your face on the attendance sheet. She writes your roll number, and everyone agrees which roll number belongs to which student. A text table works the same way. Everyone agrees “65 means A”, so Computer all over the world can understand each other.

#### ASCII : the first agreement

**ASCII** is the table that gives each English character a number. it has 128 entries, which uses 7 bits ( 2^7 = 128). it’s stored in one byte, so there’s one spare bulb. The ones to remember:

| Character | Number |
| --- | --- |
| Space | 32 |
| 0 to 9 (digits) | 48 to 57 |
| A to Z | 65 to 90 |
| a to z | 97 to 122 |

so A = 65, B = 66, C = 67 … counting up. And a = 97, b = 98 … also counting up.

Example: the word “HI”

- H is the 8th letter, so its number is 65 + 7 = 72. In binary that’s 64 + 8 = 01001000.
- i is the 9th lowercase letter, so it’s number is 97 + 8 = 105. In binary that’s 64 + 32 + 8 + 1 = 01101001.

so “HI” is stored as: 01001000   01101001 . That’s 2 letters, 2 bytes, 16 bulbs.

#### Two cool facts

1. Capital and small letters differ by exactly 32. A is 65 and a is 97 (a difference of 32). Look at the binary :
    - A = 01000001
    - a = 01100001
    
    only one bulb is different : the 32s bulb. So turning a capital into a small letter is just flipping one switch. programs do this very fast.
    
2. the digit “5”is not the number 5. The character “5” is stored as *53* , the number for the symbol. The real number 5 is stored as 00000101. They look similar, but they’re different things. A computer uses the roll number for the symbol when it’s showing you text, and the true, and the true value when it’s doing math. mixing these up is a classic beginner bug.

#### Unicode : the bigger agreement

**ASCII** only knows English. What about Telugu, Hindi, Chinese, Arabic, or emojis?

There aren’t enough numbers in 128 spots (or even 256) for all of them.

**Unicode** is the biggest table. it gives a number to every character in every language, plus emojis. It has over **140,000 entries**. The first 128 are the same as ASCII, so old and new text still match. that’s why “A” is 65 in both.

Unicode needs more space than one byte per character, so the most popular way to store it is called **UTF-8** . It’s smart: English letters still takes 1 byte, but other characters take 2, 3, or 4 bytes. An emoji like 😃 takes 4 bytes. So the word “hello” is small, but “hello 😄” is bigger than you’d think.

#### Understanding check

So, one byte has 256 patterns 2^8 = 256 but the no.of patterns are a lot more than 256 nearly 140k chars including most of languages, emojis, symbols, alphabets, digits, and more so one byte is never enough for stores all of those patterns.

Your formula says n bulbs give **2ⁿ patterns**. With about **140,000** characters, you’d need **2ⁿ ≥ 140,000**. Since **2¹⁷ = 131,072** is too small and **2¹⁸ = 262,144** is enough, you’d need **at least 18 bulbs**. 

<u>That’s why Unicode characters can’t fit in 1 byte, and why UTF-8 uses 1 to 4 bytes depending on the character.</u>
